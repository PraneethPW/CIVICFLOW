# CivicFlow AI

A React + Express civic-service workspace with a Capacitor Android app. Citizens prepare requests and upload documents; officers review them and publish live application and complaint updates.

**These are CivicFlow records. The app does not submit requests to government systems or fetch official government status.** Eligibility and delay scores are guidance from local rules, not authoritative decisions or a trained prediction model.

## Install on another laptop

Install Git and **Node.js 24 LTS** (npm is included). Then run these commands in Terminal, PowerShell, or Command Prompt:

```sh
git clone https://github.com/PraneethPW/CIVICFLOW.git
cd CIVICFLOW
npm run setup
npm run install:all
npm run dev
```

Open **http://localhost:5173**. API health: **http://localhost:4500/api/health**.

`npm run setup` creates `backend/.env` with a random JWT secret and an admin password. It preserves existing configuration. Sign in as `admin@civicflow.ai` using the `ADMIN_PASSWORD` value in that file, then open **Officer** in navigation. Citizens register their own accounts. The old public demo password is no longer provisioned.

No database account is required for local use. SQLite saves users, applications, notifications, and complaints in `backend/data/civicflow.sqlite`; uploaded files are in `backend/data/uploads/`. Do not delete these folders if you want to retain your records.

For Android Studio setup, phone installation, Windows/macOS/Linux instructions, LAN networking, hosted builds, and troubleshooting, see **[Android installation guide](docs/ANDROID.md)**.

## What works in real time

- Authenticated server-sent events notify the applicant and officers of application creation, uploads, document verification, status transitions, complaints, and notification read changes.
- Dashboard, tracking, and officer queues refetch current records on changes. Streams reconnect automatically, refresh on reconnect, and have a 30-second recovery poll. The connection bar shows live/reconnecting/offline status.
- Citizens upload actual PNG, JPEG, or PDF documents (8 MB maximum) against a checklist. Files can only be retrieved by their owner or an officer.
- English image OCR uses Tesseract, with real text and confidence. PDFs go to manual review. OCR never certifies identity, authenticity, or eligibility; an officer reviews and verifies the uploaded document.
- Officers verify documents, move applications through review/payment/approval, or reject them. The API enforces document checks, roles, ownership, and version checks to prevent stale concurrent updates.
- Complaints retain their related application, details, priority, and officer response. Citizens see responses live. Notifications belong to each citizen and retain read state.
- Users and workflow records survive API restarts. Admin metrics reflect actual stored records.

Updates arrive while the app is open. This does not implement background push notifications, offline submission, payments, appointment booking, or government portal integrations.

## Configuration

See [backend/.env.example](backend/.env.example). Configuration files with secrets and machine-specific overrides are ignored by Git.

| Setting | Purpose |
| --- | --- |
| `JWT_SECRET` | Required random secret, at least 32 characters; generated by setup. Keep stable to retain sessions. |
| `DATABASE_URL` | Optional PostgreSQL URL. Empty uses local SQLite. Use a provider URL with appropriate TLS options. |
| `DATA_DIR` | Directory for SQLite, relative to backend working directory. |
| `UPLOAD_DIR` | Private uploaded files; must persist with the database. |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Provision a new officer account on first boot. Existing credentials are preserved. Password must be 12+ characters. |
| `FRONTEND_URL`, `CORS_ORIGINS` | Browser origin and optional comma-separated extra origins. Native localhost origins are already allowed. |
| `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` | Optional AI provider. Without a key, drafts/chat use local templates; translation returns an explicit unavailable error. |

Web development proxies `/api` to port 4500. A hosted web frontend can use `frontend/.env.production.local` with `VITE_API_URL=https://your-api.example/api`, or route `/api` through its reverse proxy. `VITE_*` values are public build-time configuration; never put secrets in them.

### Shared backend / multiple laptops

Point every laptop and Android build to the **same reachable backend** to share records. Separate local SQLite installations have separate accounts and records. An APK bundles the frontend; it still needs network access to an API.

For hosted usage set `DATABASE_URL` to Postgres and persist the upload directory. Postgres `LISTEN/NOTIFY` distributes live invalidations across API instances. Use a **direct/session PostgreSQL connection**, not a transaction-only pooler, for LISTEN. Multiple API instances also need shared upload storage. Existing `civic_users` and `civic_applications` tables are imported once without overwriting current records.

Use one API process with local SQLite. To move a local installation: stop the API, copy `backend/data/` and your private `backend/.env` securely, then start it on the new laptop. Never upload these files to GitHub. Back up the database and uploads together.

### Hosting requirements

Run the backend from `backend/` with Node 24 (`npm ci && npm run build && npm start`), provide the environment variables above, and expose HTTPS. A persistent disk is required for uploads even with Postgres. Do not deploy SQLite/uploads onto ephemeral storage.

The reverse proxy must support streaming `/api/events`, disable buffering/compression for that endpoint, and permit long-lived responses. Example Nginx locations:

```nginx
location /api/events {
    proxy_pass http://127.0.0.1:4500;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1h;
}
location /api/ {
    proxy_pass http://127.0.0.1:4500;
}
location / {
    root /path/to/CIVICFLOW/frontend/dist;
    try_files $uri $uri/ /index.html;
}
```

## Checks

```sh
npm run lint
npm run build
npm test
npm run android:doctor
npm run android:sync
npm run android:build
```

CI also runs the workflow against an isolated Postgres 17 service and builds an Android debug APK. Set `TEST_DATABASE_URL` to a disposable test Postgres database to run that storage path locally; tests create and remove their own schema.

The HTTP integration suite covers role/ownership enforcement, real multipart attachment, admin review and approval, authenticated live events, complaint responses, notification read state, and persistence across restart. It uses an isolated temporary SQLite database and no paid services. Set `RUN_OCR_TEST=1` when running `npm test` to additionally exercise real English OCR with a fictional image fixture. Image OCR needs internet access on first use to fetch the English language model; PDF upload/manual review works without that download.
